# Структура входных CSV

Проверены шесть файлов по зонам «Восток», «Юго-восток» и «Югоцентр». Разделитель — `;`, кодировка — Windows-1251.

## Объём

| Зона | Синтетические данные | Контрольное распределение |
|---|---:|---:|
| Восток | 66 рабочих строк | 66 строк |
| Юго-восток | 83 рабочих строки | 83 строки |
| Югоцентр | 56 рабочих строк | 56 строк |
| Итого | 205 | 205 |

В каждом синтетическом файле после заявок находятся две пустые строки и строка `Адрес офиса`. Её следует разбирать отдельно как стартовую точку инженеров, а не как заявку.

## Пригодные поля

- `Заявка` — идентификатор заявки.
- `Тип заявки BK` — верхнеуровневая категория работ.
- `Тип заявки HD` — детальный тип работ; пригоден для сопоставления навыков и нормативной длительности.
- `Начало`, `Окончание` — жёсткое временное окно VRPTW.
- `Район` — фильтр и резервный источник координат при ошибке геокодирования.
- `Адрес` — вход для геокодера.
- `Подключение` — дополнительный признак услуги; присутствует только в зоне «Восток».
- `Гигабитное подключение` — признак требуемой технологии/навыка.
- `Статус BK` — только в контрольном распределении; пригоден для проверки результата.
- `Бригада` — только в контрольном распределении; это эталонное назначение для сравнения с оптимизатором.

## Ограничения данных

- Координат, транспорта, оборудования, рабочих смен и явной длительности работ нет.
- В контрольном файле «Восток» две заявки не назначены бригаде.
- Поле `Подключение` неоднородно и отсутствует в двух зонах.
- Идентификаторы синтетических и контрольных заявок обезличены по-разному, поэтому сопоставлять строки нужно по нормализованным адресу, временному окну и типу работ, а не по ID.
- Для первой карты применены демонстрационные координаты районов. После подключения геокодера они должны заменяться координатами адресов.
