# FieldFlow

Интерфейс интеллектуального планирования выездных работ для кейса «Билайн Бизнес» на хакатоне «Лидеры цифровой трансформации».

## Что реализовано

- диспетчерский экран с картой маршрутов и очередью заявок;
- обязательное сравнение последовательного baseline и VRPTW по назначенным заявкам, активным инженерам и пробегу (итого, по зонам и каждому инженеру);
- VRPTW: жадная вставка, внутренний 2-opt/отжиг, уплотнение маршрутов по зонам;
- матрицы времени и геометрия дорог через OSRM (`/api/routing`, `/api/routing/matrix`);
- общий час симуляции и барабан времени для параллельного проигрывания инженеров;
- фильтрация по территориям: Восток, Юго-восток и Югоцентр;
- сценарий добавления срочной заявки и локальный пересчёт затронутой зоны;
- объяснение причин назначения заявки конкретному инженеру;
- адаптивная компоновка для ноутбука, планшета и телефона;
- кэш геокодирования с уровнями качества `precise`, `approximate` и `not_found`.

Интеграционные точки подготовлены для будущего подключения FastAPI, OR-Tools, PostgreSQL и Яндекс API. Браузерная эвристика остаётся воспроизводимым решением и не заявляет математически доказанную оптимальность.

## Данные

Исходные CSV используют кодировку Windows-1251 и разделитель `;`. В трёх синтетических наборах 205 заявок: Восток — 66, Юго-восток — 83, Югоцентр — 56. После двух пустых строк в каждом файле находится адрес офиса; импортёр должен обрабатывать его как стартовую точку, а не как заявку.

Контрольные распределения используются только для построения пула инженеров. Baseline проходит заявки в исходном порядке CSV и добавляет каждую в конец маршрута первого совместимого инженера в порядке входного списка. Для обоих планов действуют одинаковые навыки, оборудование, транспорт, смены, окна SLA, скорость и матрица времени/расстояний. Если назначить заявку невозможно, причина фиксируется отдельно. Процент изменения пробега показывается только при идентичном наборе выполненных заявок и проверенном геокодировании/дорожной матрице. В текущем кэше 24 из 198 уникальных адресов имеют резервные координаты, поэтому пробег представлен как оценка без процента экономии.

Адреса геокодируются бесплатными OSM-сервисами Photon и Nominatim командой `node scripts/geocode-addresses.mjs` или `node scripts/geocode.mjs`. Результаты хранятся в `data/geocoding-cache.json` и `data/geocode-cache.json`. Импорт: `node scripts/import-csv.mjs`.

В исходных CSV нет нормативов длительности, транспорта и отдельных матриц навыков/оборудования. До появления справочников приняты допущения: 45 минут на работу, автомобиль, смена 08:00–22:00. Среднее окно SLA задаётся в интерфейсе и не подменяет длительность работы.

## Локальный запуск

Требуется Node.js 22.13 или новее.

```bash
npm ci
npm run dev
```

Production-сборка:

```bash
npm run build
npm run start
```
